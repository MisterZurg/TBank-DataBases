# Тест 3

1. Что такое сущность в ER-моделировании?

- Абстрактный объект предметной области, который нужно хранить в БД

2. Что такое атрибут?

- Свойство сущности (характеристика, поле)


3. Для чего нужен первичный ключ (PK)?

- Для уникальной идентификации строки в таблице

4. Какие характеристики верны для первичного ключа?

- Значение должно быть уникальным
- Значение не может быть NULL

5. Пример связи 1:1

Студент - Студенческий билет


6. Пример связи 1:N

Студенты - Курсы


7. Когда нужна связующая таблица?

При связи многие ко многим


8. Что произойдёт, если удалить родительскую запись без внешнего ключа?

Могут появиться «висящие» данные (orphans) в дочерних таблицах

9. Зачем нужен внешний ключ (FK)?

Гарантирует целостность связей между таблицами


10. Что делает `ON DELETE CASCADE`?

Автоматически удаляет связанные строки в дочерней таблице при удалении родителя


11. Какая конструкция корректно создаёт внешний ключ?

```sql
FOREIGN KEY (user_id) REFERENCES users(id)
```

12. Какое ограничение обеспечивает уникальность значений, но позволяет `NULL`?

```sql
UNIQUE
```

13. Какое ограничение позволяет задать условие для значений?

```sql
CHECK (age > 0)
```

14. Что показывает ER-диаграмма?

- Логические связи между сущностями БД


15. Соотнесите тип связи и пример:


Один к одному студент - студенческий билет
Один ко многим студент - курс
Многие ко многим группа - студенты


16. Определите тип связи

"Есть авторы и книги. Один автор пишет много книг. У книги только один автор."

Один ко многим



17 Какой SQL-код корректно создаёт таблицу связки для связи многие ко многим (пример: студенты - курсы)?

```sql
CREATE TABLE student_course (student_id INT REFERENCES students(id), course_id INT REFERENCES courses(id));
```
